# Writing Style: Developer Docs

For README, ARCHITECTURE.md, code comments, internal docs.

- State facts and decisions directly. Skip preamble ("In this document we will...").
- Prefer a code block or table over a paragraph when the content is structural.
- Explain *why* a non-obvious decision was made; don't restate *what* the code already makes clear.
- Keep examples runnable/copy-pasteable — no pseudo-code dressed up as a real command.
- Update docs in the same change that makes them stale. Don't leave a "TODO: update docs" follow-up for something you already know needs changing.
