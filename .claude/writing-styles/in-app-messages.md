# Writing Style: In-App Messages

For UI copy: errors, empty states, confirmations, notifications, tooltips.

- State what happened and what to do next. Not "Something went wrong" — say what failed and the recovery action if there is one.
- No blame language ("Invalid input" over "You entered it wrong").
- No marketing tone in error/empty states — this is a utility moment, not a pitch.
- Confirmations for destructive actions state the consequence plainly ("This deletes X permanently" not "Are you sure?").
- Keep it short enough to read at a glance; don't explain what a button does if the label already says it.
